# TOPBARBERS — backend MVP: контракт и границы безопасности (v1)
Статус: проектирование; **не развернуто**. Прототип v9 остаётся демонстрацией. Этот документ не является разрешением принимать реальные данные.

## Размещение
- Публичный каталог: без изменений.
- Закрытые API, БД, приватные фотографии и резервные копии: после выбора и юридической проверки российского хостинга.
- Пока хостинг не выбран, **не подключать** демонстрационную анкету к настоящему API.
- Существующих шестерых мастеров не мигрировать автоматически.

## Маршруты (предварительный контракт)
| Метод | Путь | Доступ | Назначение |
|---|---|---|---|
| GET | /api/invitations/:token/status | По токену | Только действителен/истёк; без персональных данных |
| POST | /api/applications | По действующему приглашению + Turnstile | Создать отдельную приватную заявку |
| PUT | /api/applications/current | По приватной сессии заявки | Изменить собственный черновик |
| POST | /api/applications/current/media | По приватной сессии заявки | Загрузить и проверить фото |
| POST | /api/applications/current/submit | По приватной сессии заявки | Подать анкету |
| GET | /api/admin/applications | Админ + MFA | Список заявок |
| GET | /api/admin/applications/:id | Админ + MFA | Все поля, адреса, приватные медиа и согласия |
| POST | /api/admin/applications/:id/decision | Админ + MFA | approve/reject/changes_requested |
| POST | /api/admin/invitations | Админ + MFA | Выпустить 256-битный токен на 5 дней |
| POST | /api/admin/invitations/:id/revoke | Админ + MFA | Отозвать ссылку |
| POST | /api/admin/publications/:id/hide | Админ + MFA | Скрыть публикацию |

## Инварианты
1. Токен создаёт серверный CSPRNG (32 случайных байта, base64url); в БД хранится только SHA-256. Никогда не помещать сырой токен в исходники, GitHub, журналы или аналитику.
2. Проверка срока и отзыва на сервере; общий токен допускает несколько **изолированных** заявок. Черновики открываются только через отдельную HttpOnly Secure SameSite-сессию; один токен не открывает чужие данные.
3. Истечение приглашения блокирует **новые** заявки; существующие submitted остаются на модерации.
4. Сервер валидирует поля, адреса, URL записи (HTTPS + allowlist согласованных сервисов), лимиты запросов и фото. Ссылки проверяются без небезопасного серверного обхода произвольных URL (SSRF).
5. Медиа хранятся приватно, с серверной проверкой сигнатур, перекодированием, удалением EXIF и ограничением размеров. Никаких публичных URL до модерации и отдельного согласия.
6. Одобрение и публикация — **разные операции**. Все изменения статуса и версии фиксируются в журнале, публикация только из одобренной версии.
7. Публикационный экспорт содержит только разрешённые публичные поля, никогда контакты для администрирования, согласия, токены, черновики или приватные медиа.
8. Изменения опубликованного профиля проходят новую модерацию; предыдущая версия видна до одобрения. Отзыв согласия и скрытие должны запускать процедуру удаления из публичных копий и CDN.
9. Нужны реальные серверные MFA, CSRF, rate limiting, резервное копирование, мониторинг и тестирование доступа между двумя заявками. UI-чеклист не нужен — решения в админке остаются простыми.
10. Тексты согласий, политика, уведомление РКН и требования трансграничной передачи проверяются до реального запуска.

## Следующий критерий готовности
Выбрать подходящего провайдера РФ и проверить фактическое размещение основной БД, медиа, логов и бэкапов, условия договора и стоимость. Затем реализовать API в **непубличном** тестовом окружении с синтетическими данными и автоматическими тестами. Только после этого подключать UI.
